# ContextCypher domain migration

**Scope:** Current document backend and standalone workbench integration, inspected 6 September 2026. The byte-fidelity and read-only rendering gaps below remain unfixed by this documentation revision.

The authoritative source is `S:/Development/contextcypher`. The commercial copy is excluded. ContextCypher's `src/components/DiagramEditor.tsx` saves plaintext JSON containing `systemName`, `nodes`, `edges`, `metadata`, `analysisContext`, `zoneConfiguration`, `windowLayout`, `grcWorkspace`, `attackPaths`, and `threatModelUserState`. Older documents can carry drawings and manual analysis separately. The new domain module preserves every JSON field rather than projecting onto the older, incomplete `SavedDiagramData` interface in `AnalysisTypes.ts`.

`src/security-workspace/contextcypher.ts` owns format validation and pure domain operations. Root persistence owns file access, permissions, audit, revisions and concurrency; transports must not duplicate these rules. The Guardian envelope is `{format: 'guardian-context', version: 1, original: {encoding: 'base64', data, sha256}, document}`. When the backend receives the original raw content, its UTF-8 bytes, including BOM and whitespace, survive imports, graph edits, original exports and reimports. Original provenance is frozen by helpers and must remain immutable in the store. Its digest checks integrity, not authenticity: an attacker who can rewrite the archive can recompute it. Editable document data is never trusted security policy, execution instructions or verified evidence.

**Open browser-import gap:** `GuardianWorkbench.tsx` currently parses an uploaded JSON file and serializes the object before calling `projects.import`. The stored original is therefore that serialization, not the exact uploaded bytes; a BOM can also fail at the browser parse step before the backend's supported BOM handling. The required correction is to carry raw uploaded content through the import boundary and test this user path with whitespace/BOM-sensitive fixtures. Backend unit roundtrips do not establish browser-path byte fidelity.

`importContextCypher(text)` accepts either source JSON or a version 1 Guardian envelope. `inspectContextCypher(value)` returns validity, format, errors, warnings and graph counts without throwing. `exportContextCypher(envelope, format)` exports the Guardian archive, editable source JSON (`contextcypher`) or exact original (`original`). `updateContextDocument` validates and clones replacement data; `getContextGraph` returns detached graph data and `updateContextGraph` updates nodes/edges while preserving other domains. Graph IDs stay unchanged unless explicitly edited, and references must remain valid. Missing/duplicate IDs, dangling edges, missing parents and parent cycles fail atomically; invalid objects are never silently dropped.

Bounds are 16 MiB per source/document, 64 MiB per envelope input, 64 nesting levels, 300,000 JSON values, 20,000 nodes and 50,000 edges. Validation rejects prototype-related keys, getters, non-finite numbers, cycles, sparse arrays, unsupported envelope versions and corrupt provenance. Both graph arrays are required; empty arrays are valid. Historical snapshots and cross-diagram GRC references remain intact, and are not claimed to be globally validated. An original import that fails validation leaves no partially repaired workspace.

No encrypted workspace export was found in the authoritative save path. The separate `SecureStorageService` encrypts browser provider credentials; importing those into Guardian would be incorrect. Recognizable encrypted envelopes are rejected with an instruction to export plaintext workspace JSON from ContextCypher. The module does not guess keys, import credential stores or silently discard encrypted sections. Raw encrypted/binary input fails with the same supported-format guidance.

`getLinkedContext` follows explicit diagram, asset, finding and risk IDs into implemented controls and statements of applicability. It returns detached records and does not infer relationships from labels. `calculateContextRisk` uses ContextCypher's likelihood-times-impact calculation, configured rating bands/legacy thresholds and inclusive base appetite threshold. It intentionally rejects unknown scale IDs instead of the source's zero-score fallback. It is a base scoring operation, not a scoped risk rescore: domain/tier/criticality appetite rules, assessment workflows and historical risk snapshots remain preserved and require their own explicit operations.

Attribution: document field names and risk-scoring semantics derive from ContextCypher, distributed under Apache License 2.0 (the source repository's `LICENSE`). The backend risk calculation is adapted from `src/services/GrcWorkspaceService.ts` (`calculateRiskScore`, `deriveRating`, legacy threshold/color defaults), with strict validation, pure outputs and no generated timestamps. That backend module does not depend on the source UI or provider implementation.

The restored standalone workbench in `web/contextcypher/` copies and adapts ContextCypher's editor, GRC, examples and supporting UI code. Its provider workflows use Guardian's shared authenticated operations service. Original comments and bundled attribution are retained; source provenance and the integration changes are recorded in [the workbench notice](../../web/contextcypher/NOTICE.md). Guardian's Apache-2.0 license applies to its modifications, not automatically to third-party framework content or vendor artwork.

The security distribution includes that notice and [the reference dataset attribution](../../web/contextcypher/src/data/security-knowledge-base/README.md). CSA CCM and IEC 62443 datasets are excluded from the bundled catalogue and application build. Users can import permitted CSV/XLSX control sets; existing workspace controls and references remain preserved. Dataset and vendor-icon terms remain separate from Guardian's application license; attribution does not itself grant redistribution rights.

**Open read-only rendering gap:** principals without project-write permission currently use `web/security/systems.tsx`, which renders generic asset cards rather than the restored ContextCypher node/zone renderers. The target is equivalent read-only diagram fidelity without mutation authority. This gap does not authorize dropping original diagram capabilities.

The focused tests cover exact byte and semantic round trips, edit/export/reimport, unknown fields across GRC/manual/drawing state, invalid graphs, untrusted JSON, envelope tampering, encryption detection, link retrieval and custom scoring. Product services must additionally test authorized import/export and immutable provenance under real persistence updates.
