# Local security distribution

Guardian runs locally on Windows and macOS, or privately on your infrastructure. Install Node.js 24.14.0 or newer with npm before starting. This package does not bundle Node or install an elevated service.

From a clean checkout with dependencies installed, run `npm run package:security`. It builds the backend and security UI, creates `build/security/guardianagent-VERSION-PLATFORM-ARCH`, installs locked production dependencies with install scripts disabled, checks startup help, and produces `build/security/guardianagent-VERSION.tgz`. Existing distribution directories are never overwritten; move the prior output aside or intentionally remove that exact directory before rebuilding. Reproducible here means locked inputs and a fixed content policy, not a claim of byte-identical archives across platforms or npm versions.

The directory is immediately runnable on the build platform. Double-click `Guardian.cmd` on Windows or run `./Guardian.command` from Terminal on macOS. Both start a foreground process; Ctrl+C stops it. Paths containing spaces are supported. Pass `--port 3007` to avoid another Guardian process. First launch initializes a private administrator file in the normal user data directory. Set `GUARDIAN_SECURITY_HOME` or pass `--data-dir PATH` to select a different private state directory. The launcher prints the credential file path, never its contents. Use `--help` to validate startup without initializing data.

For another machine or platform, extract the npm tarball, open its `package` directory, and run `npm ci --omit=dev --ignore-scripts`, then the platform launcher. The tarball retains the production lock as `npm-shrinkwrap.json` (npm excludes `package-lock.json` from published archives) and contains no node_modules; install on the target platform. npm is needed for installation, not ordinary startup. A source checkout remains supported with `npm ci`, `npm run build`, and the documented start-security scripts.

Packaging permits only the compiled JavaScript dependency closure rooted at `dist/security-main.js`, static assets under `web/security/dist`, the production manifest/lock, license, security operator/packaging guides, and launchers. The installed directory additionally contains locked production dependencies. Legacy entrypoints/UI, TypeScript sources/maps, local configuration, state, tokens, import archives, environment files and developer dependencies are excluded. Unexpected dependencies, dynamic module paths and symlinks fail packaging instead of widening the allowlist.

Run `npm run test:package` for packaging policy and launcher regression tests, and `npm run test:production` for clean production installation and authenticated API/UI smoke coverage. Release acceptance still requires running the produced package on real Windows and macOS machines. macOS launcher execution is exercised only when the test runs on macOS or another POSIX host; Windows runs the actual batch launcher. Fixture tests do not establish native platform support.

This is an unsigned local alpha distribution. Code signing/notarization, native installers, elevated service identity, tamper protection and verified automatic updates remain release gates; none is simulated or claimed by this package. The legacy installer and portable scripts must not be used for a Guardian 2 security release.
